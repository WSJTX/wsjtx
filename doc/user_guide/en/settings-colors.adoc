.Decode Highlighting

* _WSJT-X_ uses colors to highlight decoded CQ messages of particular
  interest.  Check the box *Show DXCC, grid, and worked-before status*
  on the *File |Settings | General* tab, and any boxes of interest to you on
  the *Colors* tab.  You can drag any line up or down to raise or
  lower its logical priority.  Right-click any line to set a new
  foreground or background color.  Foreground and background colors
  are applied separately, and careful choices of foreground,
  background, and priority can provide two indications of
  worked-before status.

* Press the *Reset Highlighting* button to reset all of the color
  settings to default values.

* Check *Highlight by Mode* if you wish worked-before status to be per
  <<INTRO,mode>>.

* Check *Only grid Fields sought* if you are only interested in the
  leading two character grid locator Fields rather than the four
  character grid locator Squares.

* Check *Include extra WAE entities* if you are interested in the
  extra entities defined for DARC WAE and CQ Marathon awards.

* Worked-before status includes `wsjtx_log.adi` in your log directory.
This is the writable primary log: new contacts logged in _WSJT-X_ are
appended here. You can still replace this file with an ADIF export
from your station logging application and click *Rescan ADIF Log*.

* Click *History sources...* to select additional ADIF files as
read-only history. These files contribute to worked-before highlighting
without copying their contacts into the primary log. _WSJT-X_ does not
append to, rewrite, or erase these files. Removing a source from the
list does not delete it.

* Source changes take effect when you accept *Settings* with *OK*;
*Cancel* discards them. Loading then runs in the background. Click
*Rescan ADIF Log* after updating an external file; Rescan uses the saved
sources, including the primary log, rather than unaccepted changes.

* Scan results appear briefly in the main window status bar and remain
visible on *Colors*. Scan failures do not open a warning dialog, including
at startup. *History sources...* shows the source paths and error details.

* If the primary log ends with an incomplete or invalid record, completed
records before the error remain available and the scan reports incomplete
history. The file is not repaired or rewritten. A supplemental source
with an unrecoverable error contributes no records. The result distinguishes
files loaded completely, primary files partially recovered, and failed files.
Empty files and files containing only whitespace supply empty history.

* Previous file history remains in use only until the new load completes.
If no file supplies usable history, previous file history is cleared.
Contacts logged while loading remain available. Correct or remove a
failed supplemental source, or correct the primary log, and rescan to
restore complete history. An absent primary log is normal before the
first contact is logged. Counts refer to unique worked-before entries,
which may be fewer than the number of contacts.

* An additional path that resolves to the primary log is marked *Same file
as primary log*. It is scanned only once; new contacts still change that
file through the primary log path. Stored paths are preserved so aliases
can be retargeted and unavailable files can be restored.

* ADI files normally contain ASCII text. For compatibility with other
logging applications, UTF-8 exports using byte-counted or character-counted
field lengths are also accepted. Byte-counted lengths take precedence when
both interpretations are valid.

.Logbook of The World User Validation

Stations who are known to have uploaded their logs to the ARRL LoTW
QSL matching service can be highlighted. The data used to determine
this is available online.

* *Fetch Now* will download a fresh dataset from the *Users CSV file
   URL*. The LoTW team normally update this data weekly.

* Adjust *Age of last upload less than* to set the period within
  which a station must have uploaded their log to LoTW to trigger
  highlighting.

.Alternative Highlighting

Some users find an alternative color scheme with pastel-like colors
easier on the eyes and more suitable for the dark style. You can
select either the original _WSJT-X_ or the alternative style.  With
the alternative style, stations uploading their logbook to LoTW will
have black foreground color, others red. Stations worked-before are
displayed with grey background.

image::highlighting.png[align="center",alt="Decode Highlighting"]

It is still possible for you to customize the color scheme according
to your own preferences. In addition, you can highlight individual
callsigns, grids, prefixes, or directional CQ calls such as DX, POTA,
and SOTA with an orange or blue background. Callsigns, grids, and
directional calls are separated by commas and can be mixed (e.g.
"K1JT, DG2YCB, JO33, DX, POTA, SOTA,"). Spaces after commas are
allowed. Directional calls are matched as whole list items, so list
order has no effect and no leading comma is needed. A single
directional call does not need a comma. You must include a comma after
each callsign or grid, and also at the end of the line.
Prefixes must be followed by a semicolon (e.g. "VK;ZL;T88;"). The
Wanted audible alert uses the same orange and blue entries.
