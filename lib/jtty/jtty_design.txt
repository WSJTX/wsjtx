JTTY: A possible WSJT mode for fast RTTY-like contest exchanges

Our general goal is an operational feel similar to standard ham RTTY.
Weak-signal performance is much better that RTTY, error rate much
smaller. JTTY transmissions can start at any time and have any length,
but typically are short. Any arbitrary message (capital letters,
digits, spaces, punctuation) can be sent, but source-encoding is
especially well optimized for the short, fixed-format messages used in
RTTY-style contesting.

A JTTY transmission is composed of one or more packets, each with a
synchronising sequence followed by a data block with 32-bit
payload. Two payload bits select one of 4 possible message types; the
remainder convey details of user information for that type. The
payload is large enough to convey a standard callsign plus flags to
convey message words such as "CQ", "TU", "599", "AGN?", and "TU
NOW". Alternatively, a packet may convey a sequence of any five
characters chosen from a 64-character ASCII subset.

To ensure decoded message integrity, a 10-bit CRC is appended to each
32-bit payload. The result is then encoded using a strong binary block
code with parameters (n,k) = (80,42). The code is a shortened form of
the (128,90) LDPC code used for MSK144.

Each transmitted JTTY packet starts with the Barker 13 binary sequence
for syncronization, transmitted using 2-tone frequency shift
keying. The 80 information-carrying bits are then sent using
Gaussian-smoothed 4-tone frequency-shift keying, 4-GFSK, and thus two
information-carrying bits per symbol. Altogether there are 13 + 80/2 =
53 channel symbols per packet. At the currently selected symbol rate,
12000/384 = 31.25 baud, a JTTY packet is transmitted in 1.696 seconds.
Signal bandwidth is 4 * 31.25 = 125 Hz.

Source encoding is optimized for the message formats typically used in
RTTY-style contesting, with one principle difference: repetition of
important message fragments such as callsigns and contest exchange
information is not needed, since JTTY's strong FEC already implies
reliable copy. Most contest-style transmissions require only one or
two packets. There is no need for archaic RTTY contesting necessities
such as CR/LF at start of a transmission, LETTERS/NUMBERS shift
characters, an extra space at end-of-message, etc. Real throughput for
JTTY in contesting circumstances will be significantly higher than
for 45-baud RTTY.
